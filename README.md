# Piv-Anima
Roguelike Game "Piv Anima" from MeriDiana studio.

# Piv Anima — структура Unity-проєкту

Цей документ пояснює, куди потрібно додавати файли в проєкті.  
Головне правило: **не створюйте нові папки без потреби і не складайте файли у випадкові місця**.

## Структура `Assets`

```text
Assets/
├── Art/
├── Audio/
├── Data/
├── Prefabs/
├── Scenes/
├── Scripts/
└── Settings/
```

### `Art`

Усі графічні ресурси гри.

Приклади:

```text
Art/
├── Sprites/
├── Animations/
├── Materials/
└── VFX/
```

Сюди додаємо:
- спрайти персонажів;
- спрайти ворогів;
- тайли та оточення;
- іконки;
- анімації;
- матеріали;
- візуальні ефекти.

Якщо певного типу файлів ще немає, не потрібно створювати для нього порожню папку заздалегідь.

---

### `Audio`

Усі звукові файли гри.

Приклади:

```text
Audio/
├── Music/
└── SFX/
```

`Music` — фонова музика.

`SFX` — звукові ефекти:
- атаки;
- кроки;
- отримання шкоди;
- смерть ворогів;
- UI-звуки;
- інші короткі ефекти.

---

### `Data`

Дані гри, які не є безпосередньо логікою.

У першу чергу сюди будуть додаватися `ScriptableObject`.

Приклади:

```text
Data/
├── Items/
├── Weapons/
├── Enemies/
└── Rooms/
```

Тут можуть зберігатися:
- характеристики предметів;
- характеристики зброї;
- характеристики ворогів;
- параметри кімнат;
- інші конфігураційні дані.

Підпапки створюємо тільки тоді, коли вони реально потрібні.

---

### `Prefabs`

Готові Unity-об'єкти, які використовуються повторно.

Приклади:

```text
Prefabs/
├── Player/
├── Enemies/
├── Items/
├── Rooms/
└── UI/
```

Сюди додаємо:
- prefab гравця;
- prefab ворогів;
- prefab предметів;
- prefab кімнат;
- UI prefab;
- інші повторно використовувані GameObject.

Не зберігайте prefab у `Scenes` або `Scripts`.

---

### `Scenes`

Усі `.unity` сцени гри.

Наприклад:

```text
Scenes/
├── MainMenu.unity
├── Game.unity
└── Test.unity
```

Можливі сцени:
- головне меню;
- основна ігрова сцена;
- сцена вибору персонажа;
- тестові сцени.

Якщо створюється тимчасова тестова сцена, дайте їй зрозумілу назву.

---

### `Scripts`

Увесь C# код гри.

На початку не потрібно створювати десятки підпапок.  
Папки додаються разом із появою відповідних систем.

Приблизна структура:

```text
Scripts/
├── Core/
├── Player/
├── Combat/
├── Enemies/
├── Items/
├── Rooms/
└── UI/
```

#### `Core`

Базові системи гри, які не належать до конкретного персонажа або ворога.

Наприклад:
- `GameManager`;
- `RunManager`;
- завантаження сцен;
- загальні стани гри.

Не потрібно складати сюди всю логіку гри тільки тому, що вона "важлива".

#### `Player`

Код, який стосується гравця.

Наприклад:
- рух;
- ввід;
- керування персонажем;
- анімації гравця;
- специфічні здібності гравця.

#### `Combat`

Спільна бойова логіка.

Наприклад:
- здоров'я;
- отримання шкоди;
- projectiles;
- базова логіка зброї;
- `IDamageable`.

Якщо код однаково потрібен і гравцеві, і ворогам, скоріше за все він повинен бути тут, а не дублюватися у двох папках.

#### `Enemies`

Код ворогів.

Наприклад:
- AI;
- рух ворога;
- атаки;
- спавн;
- спеціальна поведінка окремих типів ворогів.

#### `Items`

Код предметів.

Наприклад:
- підбирання предметів;
- ефекти предметів;
- інвентар;
- модифікатори характеристик.

Самі дані предметів бажано зберігати в `Data`, а не безпосередньо в коді.

#### `Rooms`

Код кімнат та генерації рівня.

Наприклад:
- керування кімнатою;
- відкриття дверей;
- спавн ворогів у кімнаті;
- вибір наступної кімнати;
- генерація рівня.

#### `UI`

Код інтерфейсу.

Наприклад:
- HUD;
- меню паузи;
- головне меню;
- екран смерті;
- налаштування.

---

### `Settings`

Налаштування Unity та Render Pipeline, які використовує сам проєкт.

Наприклад:
- URP settings;
- 2D Renderer settings;
- інші Unity assets конфігурації.

**Не видаляйте та не переносіть файли з цієї папки без причини**, оскільки на них можуть посилатися налаштування проєкту.

---

# Загальні правила

1. Не створюйте нову папку тільки "на майбутнє". Створюйте її, коли з'являються відповідні файли.
2. Назви файлів, класів, prefab і папок повинні бути зрозумілими.
3. Не складайте C# скрипти в `Art`, `Prefabs`, `Scenes` тощо.
4. Не складайте всі скрипти в одну папку `Scripts` без поділу, коли їх стане багато.
5. Не створюйте окремі дублікати однакової логіки для Player та Enemy, якщо її можна зробити спільною.
6. Не змінюйте чужу велику систему без попередження відповідального за неї.
7. Працюйте з Unity `.meta` файлами разом з основними файлами — вони повинні залишатися в Git.
8. `Library`, `Temp`, `Logs`, `UserSettings` та інші локальні Unity-файли не повинні потрапляти в Git.
9. Якщо не впевнені, куди додати новий файл — запитайте команду перед створенням нової структури.
